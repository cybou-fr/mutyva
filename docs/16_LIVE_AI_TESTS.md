# Сквозной тест с реальным ChatGPT

Этот тест запрашивает вход человека, затем сам отправляет реальные запросы и проверяет ответы. Он использует production ChatSession, AiChat, SSE-декодер, AppDocument и хранилище поколений. Заглушек и API-ключей в этом запуске нет.

## Запуск в Windows

После первоначальной настройки CMake/Qt и развёртывания Qt-зависимостей в Release:

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_live_ai_test.ps1
```

Либо запустить собранный `build-msvc/Release/live-ai-tests.exe --report <absolute-report-path>`. Откроются окно проверки и системный браузер. Пользователь только завершает Continue with ChatGPT и согласие. Затем все три сценария идут автоматически, без ввода запросов и скриншотов.

## Что проверяется

1. Реальный ответ AI без изменения интерфейса: получение моделей, отправка запроса, полный SSE, финальный текст, проверка envelope, ответ в чате. Поколение не меняется, предпросмотра нет.
2. Реальная мутация: AI добавляет humidity-card после forecast. Проверяются сохранение всех старых виджетов, количество и порядок. Предложение автоматически применяется только к изолированному тестовому приложению, затем новый AppDocument восстанавливает сохранённое поколение и сравнивает декларацию.

Настоящие приложения и заметки пользователя не читаются и не изменяются. Контекст строится из bundled City Pulse в отдельной временной папке. Только регистрация ChatGPT/host ID переиспользуется; токены получаются в браузере и остаются в памяти тестового процесса. Требуется один вход на весь запуск. Три реальных запроса расходуют доступные лимиты подключённого аккаунта.

3. Город по умолчанию: AI получает обычный запрос про Poitiers. Проверяется изменение только настройки city-search.defaultCity, отсутствие изменений остальных виджетов, сохранение и восстановление настройки в новом AppDocument.

## Отчёт и коды выхода

Отчёт JSON пишется атомарно по мере выполнения: waiting_for_sign_in → running → passed/failed/cancelled. В нём есть состояния сценариев, длительность, фиксированная диагностика и короткий проверенный ответ AI на тестовый запрос. Токены, headers, raw SSE, account identity и содержимое пользовательских данных не включаются. Отчёт запуска по скрипту: build-msvc/live-ai-report.json.

- 0: все реальные сценарии прошли, включая сохранение и восстановление.
- 1: ошибка входа, запроса, результата или проверки.
- 2: пользователь отменил проверку/закрыл её окно.
- 3: ошибка инициализации UI или записи отчёта.

Вход ограничен 10 минутами, каждый сценарий — 4 минутами; сетевые ограничения самого клиента также действуют. При ошибке тест останавливается и сохраняет диагностику. Никакого автоматического обхода согласия, повторной оплаты или подмены провайдера нет.

## CTest

Обычный ctest по-прежнему запускает быстрые офлайн-тесты. Чтобы явно включить интерактивный live-тест:

```powershell
cmake -S . -B build-msvc -DMUTYVA_ENABLE_LIVE_AI_TESTS=ON
ctest --test-dir build-msvc -C Release -R '^live-ai$' --output-on-failure
```

У теста labels live/interactive и timeout 1200 секунд. Запуск требует рабочего стола и человека для входа. Не включать этот флаг в безлюдном CI без отдельного проекта управления тестовыми аккаунтами.

Сам оркестратор дополнительно проверяется офлайн на подставном транспорте: автоматический проход сценариев, ошибка HTTP, отмена, report и exit codes. Эти офлайн-проверки не заменяют реальный запуск. Называть live-тест пройденным можно только по финальному отчёту status=passed со всеми успешными сценариями.
