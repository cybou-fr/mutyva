# Город погоды по умолчанию

В чате можно попросить: «Показывай по умолчанию погоду в Poitiers». AI получает доступное свойство из каталога и предлагает обычную проверяемую мутацию. Смена города не требует пересборки приложения и не добавляет разрешений.

## Контракт

У city-search появилось необязательное defaultCity: строка до 100 символов, после trim — минимум 2. Оно доступно addWidget/updateProperty и полной декларации только для этого вида. Без настройки используется Paris, поэтому старые документы совместимы без миграции. Версия схемы остаётся 2.

Погода общая для приложения. Если поисков несколько, все наследуют явно заданный defaultCity; несколько явных значений должны совпадать без учёта регистра и внешних пробелов. Конфликтующие декларации отклоняются. Отдельные города для независимых погодных панелей пока не поддерживаются.

Пример ответа: [default-city-poitiers-response.json](../examples/designer/default-city-poitiers-response.json). Свойство хранится в поколении интерфейса, а не в пользовательской SQLite-базе.

## Поведение

- В предпросмотре поле показывает будущий город, но поиск отключён и новые данные не запрашиваются.
- После «Применить» WeatherService получает сохранённый город и загружает погоду/воздух.
- После перезапуска город берётся из последнего сохранённого документа, без AI.
- Отмена не меняет город. Восстановление старого поколения возвращает его настройку.
- Обычный поиск другого города остаётся временным действием; он не меняет defaultCity и не создаёт поколение. Редактирование заголовка или подготовка AI-контекста не сбрасывает этот выбор.
- Во время смены города старые температура/влажность/ветер скрываются до получения новых данных. Ответы предыдущего поиска игнорируются, чтобы Paris не перезаписал Poitiers при медленной сети.

## Проверки

Офлайн-тесты проверяют schema/catalog/context, предложение AI, preview/cancel/apply/restart/rollback, неверный вид/лимиты/конфликты, поле QML и его блокировку в preview. WeatherService проверяется подставным HTTP-транспортом: запрос города появляется только после Apply, а медленный старый поиск не меняет новые данные.

Live-suite дополнен третьим настоящим запросом «Показывай по умолчанию погоду в Poitiers». Он проверяет изменение только city-search.defaultCity, сохранение остальных виджетов, применение в изолированном приложении и восстановление defaultCity после пересоздания AppDocument. См. [16_LIVE_AI_TESTS.md](16_LIVE_AI_TESTS.md).

## Реальный результат

19 октября 2026 расширенный live-suite прошёл все три сценария. ChatGPT ответил на запрос про Poitiers, предложил изменение defaultCity, а тест подтвердил применение и восстановление сохранённой настройки. [Отчёт](evidence/live-ai-default-city-2026-10-19.json). Погодные HTTP-запросы, гонки и QML проверены отдельно среди 60 офлайн-тестов; сам live-suite не запрашивает погоду и не изменяет приложение пользователя.
